# RKN Associates Public PWA — 27 October 2026

## Implementation

The public website keeps the latest HVD typography, Safari cursor, six published CMS routes, and opt-in visitor analytics. Its installable app is added by the **public renderer** only, never the private CMS preview:

- `/manifest.webmanifest`: site name `RKN Associates`, start `/home`, scope `/`, `display: standalone`, RKN 192/512 px icons.
- iOS: Apple standalone/appearance metadata and 180 px touch icon.
- `/assets/rkn-pwa.js`: registers the root service worker only in a secure context after page load. Registration errors do not block the website.
- `/service-worker.js`: cache only `/offline.html`; for same-origin page navigations fetch live content and fall back to the offline notice when disconnected. **No caching** of website analytics, customer form/checkout requests, CMS/API routes, POST requests, or private details.
- `/offline.html`: explains that orders and forms require internet access. No fake order success, offline queue or browser-side payment handling.
- Vercel headers explicitly provide manifest MIME and no-cache service-worker update behavior.
- The dynamic Interior page gets a visually hidden accessible H1. The visible `Privacy settings` button has an accessible name that starts with its visible text, repairing the latest automated Axe scan finding.

## Verification

`node --test tests/*.test.cjs` runs consent/origin/HVD/cursor/PWA unit tests. A real Chromium smoke test confirmed service-worker activation, manifest standalone mode, offline navigational fallback, and that `/api/shop` is **not** available from an offline cache.

Final public live release checks should verify MIME, icon assets, six page HTTP 200 responses, accessibility at 320/390/768/1365px, and the zero-cache boundary. This does **not** substitute for the owner's acceptance of a physical iPhone/Android Add-to-Home-Screen installation; installation menus vary by browser and OS.

## Operational constraints

The custom domain is still controlled by the registrar and remains outside this HAOR. Use the working Vercel origin until DNS is repaired. A service worker's scope is tied to the origin: installing on the Vercel host will not automatically move the installation to a later custom domain.
